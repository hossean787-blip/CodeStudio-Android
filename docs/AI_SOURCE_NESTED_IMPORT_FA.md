# تکمیل دریافت سورس‌های تو در تو در صبا استودیو

**تاریخ:** ۱۴ آبان ۱۴۰۵ / 2026-11-05
**پایه:** main در Commit `e7d7a79a616cea0abeea3e457fe03a23382ed5f5`

## مسئله رفع‌شده

در سیزده سورس مرجع AI، مخازن `techjarves/Mobile-Harness` و `DraxonV1/Syntac` دارای فایل `.gitmodules` با زیرمخزن‌های Git هستند. مسیر قبلی «دریافت سورس» فقط درخت اصلی را با `git clone` و سپس `checkout --detach <SHA>` دریافت می‌کرد؛ زیرمخزن‌های خارجی می‌توانستند بدون محتوا باقی بمانند.

## تغییر اجراشده

برای دریافت منابع با **Commit ثابت** و فقط با درخواست صریح کاربر:

1. مخزن در پوشه خصوصی، جدید و جداگانه clone می‌شود.
2. روی SHA دقیق ثبت‌شده `checkout --detach` انجام می‌شود و SHA دوباره بررسی می‌شود.
3. `git submodule update --init --recursive --jobs=2` با محدودسازی پروتکل Git به HTTPS اجرا می‌شود.
4. `git submodule status --recursive` بررسی می‌شود؛ علامت «-» (دریافت‌نشده)، «+» (SHA ناسازگار)، «U» (تعارض)، مسیر ناامن یا وضعیت نامعتبر باعث شکست واردکردن می‌شود.
5. SHA مخزن والد دوباره تأیید می‌شود.
6. فقط پس از همه کنترل‌ها، پوشه به‌عنوان پروژه در صبا ثبت می‌شود؛ در صورت خطا پوشه ناقص پاک می‌شود و پروژه‌های فعلی دست‌نخورده می‌مانند.

## کشف و کنترل فایل‌های Git LFS

- بررسی ۱۳ مخزن نشان داد `Syntac` در فایل `.gitattributes` از `filter=lfs` برای باندل‌های runtime استفاده می‌کند.
- واردکننده، فایل‌های `.gitattributes` مخزن اصلی و زیرمخزن‌ها را بدون دنبال‌کردن پیوندهای نمادین بررسی می‌کند. در صورت نیاز، حضور `git-lfs` را تأیید می‌کند؛ اگر نصب نباشد واردکردن ناقص را ثبت نمی‌کند.
- آدرس origin خام هر مخزن باید GitHub باشد. تنظیم دلخواه `.lfsconfig` بدون بررسی امن نیست و باعث توقف ثبت پروژه می‌شود.
- برای مخازنی که Git LFS دارند، دانلود دارایی‌ها فقط از endpoint مورد انتظار GitHub انجام می‌شود. در صورت شکست/Timeout، پوشهٔ ناقص حذف می‌شود.
- وجود فایل‌های بیرون از Git و Git LFS یا سرویس‌های مالکیتی همچنان با Git قابل تضمین نیست.

## محدودیت‌ها

- این تغییر برای واردکردن معمولی مخازن GitHub که SHA ثابت ندارند اعمال نمی‌شود؛ API قبلی حفظ شده است.
- دارایی‌های Git LFS فقط در صورت نصب Git LFS و موفقیت دریافت از GitHub قابل تکمیل هستند؛ سرویس‌ها، APIها، باینری‌های بیرون از Git/Git LFS و سورس‌های خارج از Git Submodule قابل تضمین نیستند.
- زیرمخزن‌های خارجی ممکن است وابستگی و مجوز جداگانه داشته باشند؛ دریافت آن‌ها مساوی حق بازنشر یا اجرای خودکار نیست.
- هیچ‌کدام از موتورهای مستقل ۱۳ اپ به این ترتیب به APK داخلی اضافه نمی‌شوند؛ فقط سورس پروژه روی گوشی کامل‌تر وارد می‌شود.
- دریافت عملی از اینترنت روی گوشی واقعی، زمان اجرا و فضای ذخیره‌سازی لازم هنوز نیازمند آزمون روی دستگاه هستند.
- آزمون‌های `PinnedSourceSubmoduleTest` قرارداد وضعیت Git و جلوگیری از ثبت درخت ناقص را می‌سنجند. ساخت و آزمون جامع Android را GitHub Actions اجرا می‌کند.

**گام بعدی:** آداپتورهای عملی هر پروژه در Issue شماره ۹ جداگانه پیگیری شوند.
