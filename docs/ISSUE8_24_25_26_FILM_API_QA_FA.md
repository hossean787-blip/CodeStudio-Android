# صبا استودیو — گام اجرایی اصلاحیه‌های ۲۴، ۲۵، ۲۶ و وضعیت ۲۷

بازبینی: ۲۰۲۶-۱۱-۰۵. مبنا: Issue #8؛ این سند به معنی تکمیل همه معیارهای اصلاحیه‌های ۲۴–۲۶ نیست.

## ۲۴ — برش واقعی ویدئو و فایل پروژه
مسیر برنامه: «استودیوی اسناد» ← «ورود به استودیوی فیلم».

- انتخاب صریح ویدئوی محلی با Android SAF و نگه‌داشتن مجوز خواندن در صورت پشتیبانی.
- مشاهده ویدئوی انتخابی با VideoView؛ خواندن مدت فایل، تعیین شروع و پایان برحسب ثانیه با اعتبارسنجی.
- تبدیل و برش واقعی با Media3 Transformer نسخه 1.11.1 با مجوز Apache-2.0 و ذخیره MP4 با SAF؛ هنگام خطا فایل ناقص staging پاک می‌شود.
- فایل پروژه JSON ساختاریافته، UTF-8 و قابل بررسی/خواندن مجدد با نسخه فرمت، URI منبع و زمان‌های دقیق؛ محل اصلی ویدئو باید در دسترس باقی بماند.
- فایل ویدئو در پوشه خصوصی cache تا زمان خروج از صفحه قرار دارد؛ بدون آپلود یا کلید API. ذخیره در مقصد با انتخاب صریح کاربر انجام می‌شود.
- محدودیت آگاهانه: یک ویدئو و یک برش، فقط MP4. تایم‌لاین چندلایه، keyframe، موشن‌کپچر، lip-sync، VFX، هماهنگی چهره/محصول، تولید هوش مصنوعی، MOV، پیش‌نمایش چندنما و QA دستگاه واقعی هنوز اضافه نشده‌اند. این قسمت را «استودیوی فیلم کامل» ننامید.

## ۲۵ — بانک API رایگان
- بانک موجود با منبع رسمی Hugging Face Inference Providers گسترش یافت؛ چون شرایط اعتبار قابل تغییر است هیچ اتصال جعلی/ساخت کلید خودکار ندارد.
- تاریخ آخرین بررسی دستی منابع در UI فارسی/انگلیسی مشخص است؛ این تاریخ وضعیت زنده سهمیه یا قیمت نیست.
- جستجو، فیلتر، راهنمای رسمی و ورود به تنظیمات کلید امنِ موجود حفظ شدند.
- محدودیت: بروزرسانی آنلاین خودکار، آزمون حساب واقعی، هشدار اعتبار به‌صورت برخط و مقایسه جامع سرویس‌ها در این گام پیاده‌سازی نشده‌اند.

## ۲۶ — امنیت Failover
- جریان موجود FallbackProvider اکنون بازتاب کلید اصلی یا کلید مقصد را از خطا/استثنا و پیام Retry پاک می‌کند. سیاست consent، محدودیت مقصد، محرمانگی و توقف پس از خروجی جزئی محفوظ‌اند.
- آزمون‌های جدید FallbackProviderTest جلوگیری از نمایش مقادیر محرمانه را می‌سنجند.
- این کار مجوز ساخت کلید خودکار، عبور از محدودیت منطقه/حساب یا هزینه سرویس جدید نیست؛ سرویس واقعی با کلید کاربر همچنان نیاز به آزمون دارد.

## ۲۷ — وضعیت قبلی
- پیاده‌سازی مخفی‌کردن telemetry مرتبط با cache پشت جزئیات از طریق PR #11 از قبل در main ادغام شده است؛ این شاخه مجدداً آن را تغییر نمی‌دهد.

## دروازه بازبینی و ادغام
- JVM test suite و ساخت APK، شبیه‌ساز، Native/JNI و provenance باید روی HEAD نهایی این شاخه موفق باشند.
- آزمایش واقعی تولید/ذخیره MP4 روی گوشی/شبیه‌ساز با ویدئوی نمونه مجاز، تایید بازشدن خروجی و کنترل اندازه/کیفیت لازم است؛ تنها کامپایل یا تست مدل پروژه اثبات کیفیت خروجی MP4 نیست.
- آخرین main، تعارض‌های PRهای دیگر، مجوزهای کتابخانه‌ها، اندازه APK و گزارش‌های CI بازبینی شوند.
- آزمون نصب/آپدیت بدون حذف داده با کلید امضای تولیدی جداگانه ضروری است؛ APK تست‌امضا را تجاری معرفی نکنید.
- نقطه بازگشت: HEAD مخزن main هنگام ساخت شاخه؛ در صورت شکست، PR ادغام نشود.
