# صبا استودیو — ادامه نشست‌های Claude، Gemini و OpenCode

**تاریخ:** ۱۴ آبان ۱۴۰۵ — مرحله تکمیلی مستقل و انباشته روی PR شماره ۲۰

## قرارداد واقعی آداپتورها

در `AiRuntimeBridge.executionCommand` پارامتر اختیاری `sessionId` به سه موتور محدود است:

| عامل نصب‌شده در محیط پروژه | نوع شناسه | مثال دستور |
|---|---|---|
| Claude Code | UUID با ۳۶ نویسه | `claude -p --permission-mode plan --resume '<UUID>' '<PROMPT>'` |
| Gemini CLI | UUID با ۳۶ نویسه | `gemini --resume '<UUID>' --approval-mode plan -p '<PROMPT>'` |
| OpenCode | `ses_` و ۶ تا ۶۴ حرف/رقم | `opencode run --session '<ses_ID>' '<PROMPT>'` |

- هیچ نشستی از حساب یا فایل کاربر استخراج نمی‌شود. کاربر شناسه نشست خود را وارد می‌کند؛ برنامه وجود نشست را جعل نمی‌کند.
- شناسه در UI فقط در حافظه همان نمای کاری نگهداری می‌شود و هنگام تغییر پروژه یا موتور پاک می‌شود؛ `API key` جدیدی ساخته یا ذخیره نمی‌شود.
- در حال حاضر OpenCode حالت read-only تضمین‌شده ندارد و اجرای آن همچنان تأیید ویرایش کاربر را لازم دارد. Gemini و Claude از حالت‌های plan استفاده می‌کنند، اما رفتار نسخه‌های واقعی نصب‌شده باید روی دستگاه آزموده شود.
- نام عامل از allowlist ثابت است و شناسه با regex بسته اعتبارسنجی و به صورت یک آرگومان POSIX-quoted به CLI منتقل می‌شود. مسیرهای فایل، گزینه دلخواه و نام جلسه مثل `latest` پذیرفته نمی‌شوند.
- رابط اصلی در «تنظیمات ← افزونه‌ها ← منابع هوش مصنوعی» و ابزار `ai_cli_delegate` هر دو از همین قرارداد مشترک استفاده می‌کنند.
- هیچ نشست قدیمی از پروژه دیگر خودکار انتخاب نمی‌شود. UUID معتبر لزوماً به معنای موجود بودن/مجاز بودن نشست نیست؛ خود CLI آن را در محدوده حساب و workspace بررسی می‌کند.

## پذیرش و آزمون
`AiRuntimeBridgeTest` دامنه مجاز شناسه‌ها، رد رشته‌های تزریقی و رد استفاده نامعتبر روی عامل‌های دیگر را بررسی می‌کند. آزمون JVM و APK/Native روی CI GitHub اجرا می‌شوند؛ نتیجه آن‌ها باید قبل از ادغام ثبت شود. اجرای نشست واقعی روی گوشی نصب‌شده و احراز هویت‌شده هنوز انجام نشده و محدودیت نسخه آزمایشی است.

**این قابلیت انتقال تمام امکانات ۱۳ اپ مستقل نیست.** فقط اجرای یک قابلیت مشترک با سه موتور استاندارد نصب‌شده را توسعه می‌دهد.
