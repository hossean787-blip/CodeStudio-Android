# دستور مادر اجرایی صبا استودیو — ۲۶ اصلاحیه مصوب
**مخزن:** `hossean787-blip/CodeStudio-Android` | **هدف:** اپ اندروید واقعی، فارسی RTL، قابل نصب و به‌روزرسانی بدون حذف داده‌ها. این Issue سند دستور است؛ به معنای اجرای خودکار یا تکمیل کارها نیست.

## قواعد الزامی
1. هیچ کدام از ۲۶ مورد حذف، نمایشی یا صرفاً Placeholder نشود. پیش از هر تغییر مخزن و قابلیت‌های موجود را بررسی و موارد هم‌پوشان را توسعه بده؛ همه را یک‌باره و بدون آزمون در `main` نریز.
2. هر پروژه و چت ایزوله؛ تبادل اطلاعات بین پروژه‌ها فقط با دستور صریح. اصل حداقل دسترسی، رمزنگاری کلیدها، بررسی مجوزهای متن‌باز، حفاظت از اطلاعات و گزارش تغییرات.
3. ابتدا baseline و نسخه بازگشت ثبت شود. PRهای #5 (Skills)، #6 (اتصالات) و #7 (منابع AI) را بررسی کن؛ تعارض `AppNav.kt` و `ProjectNavigationSidebar.kt` را با ادغام معنایی حل کن. هیچ PR آزمون‌نشده‌ای merge نشود.
4. دستگاه هدف Android 8.0+؛ معماری Kotlin/Jetpack Compose در مخزن موجود حفظ شود؛ `applicationId=ir.sabagostar.sabastudio`. امضای APK جدید باید با نصب موجود سازگار باشد، بدون حذف اپ؛ کلید انتشار تولیدی جدا از debug.
5. خطای احراز هویت، منطقه، سهمیه و شبکه به‌طور روشن تفکیک شود. هیچ دورزدن محدودیت سرویس، ساخت کلید جعلی، کپی توکن ChatGPT یا استفاده از API پولی بدون رضایت.
6. تعریف مشترک «تکمیل»: کد واقعی + تست واحد/یکپارچه/شبیه‌ساز + بررسی امنیت + اثبات خروجی + گزارش خطا و نقطه بازگشت. امکانات نیازمند سرویس/هزینه تا اتصال و آزمون، `not configured` بمانند.

## معیارهای پذیرش
- هر گزینه منو واقعاً باز شود و یک مسیر عملیاتی تست‌شده داشته باشد؛ اگر اتصال لازم است، وضعیت راه‌اندازی شفاف بدهد.
- پروژه‌ها و کلیدها به بیرون نشت نکنند؛ مهاجرت DB با داده واقعی؛ تست بدون پاک شدن گفتگو/فایل از نسخه نصب‌شده قبلی.
- خطاهای 401/403/429 و قطع شبکه کنترل‌شده؛ API پولی یا سرویس جدید صرفاً با opt-in، بدون شکستن شرایط سرویس.
- APK غیر-دیباگِ تستی/انتشار فقط بعد از CI سبز و آزمون نصب؛ SHA-256، نسخه/commit، فایل‌ها/Artifact، گزارش آزمون و خطاها ثبت شود.
- صداقت فنی: اگر محیط، API، GPU، سرویس یا مجوزی موجود نیست، `متوقف به‌دلیل مانع` با راهکار جایگزین؛ هیچ بخش ناقصی «تکمیل و آزموده‌شده» نام نگیرد.
